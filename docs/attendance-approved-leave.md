# Approved student leave

1. Set school weekdays and holidays for each academic year/campus under Attendance → Attendance Settings. Choose All Campuses to apply the same calendar to every campus you manage, or select one campus. A bulk save requires confirmation and checks all campus versions before committing; no partial update is kept if a calendar changed. If calendars differ, the first campus is shown as a starting point with a warning. Use Add Holiday to choose dates, or enter YYYY-MM-DD dates one per line. The fallback is Monday–Friday with no holidays. Configure local holidays before recording leave.
2. In Admin-Daily Attendance select the year, campus and grade, then Record Leave. Choose one student, dates, full or partial days, reason and approver. An optional permission letter (PDF/image, up to 5 MB) is stored on the private disk and downloaded only through campus-authorized routes.
3. Review the school dates and excluded dates. Existing attendance and overlapping approved leave block submission; no records are replaced. Leave starts today or later; correct historical attendance through Edit on the daily register.
4. Today’s leave is recorded as EX immediately. Future dates remain scheduled until due. Full-day leave snapshots every period allowed for the student’s enrollment group/grade; partial-day leave snapshots the selected periods. Each date remains one attendance day.
5. Approved Leave lists the selected campus’s most recent 100 leave records. Cancel remaining or shorten a range with a reason. These actions cancel pending dates only; they retain already recorded attendance and the audit trail. Correct recorded attendance explicitly in the daily register.

The `attendance:apply-leave` command is registered with Laravel’s scheduler for 00:05 Asia/Bangkok. Running the application scheduler is an operator responsibility; this change does not install cron or deploy server settings. Due leave is also applied when an authorized user opens or saves that daily register, so the register stays correct without a scheduler. Applying due leave is idempotent and never overwrites existing marks. Conflicts are shown in the leave day statuses. Changed holiday settings, ended enrollment, or a changed campus/class/grade can skip scheduled dates rather than apply leave to the wrong register.

Leave dates and period snapshots are reviewed at approval. Later calendar changes can skip pending non-school dates; they do not silently add extra dates to an already approved plan. New requests use the current calendar and period configuration.
