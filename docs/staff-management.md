# Staff Management

HRM → Staff Management keeps Staff Information, Work Information, Education, and Previous Employment in separate tabs. Existing profile, education, employment, and linked-user records retain their IDs and values when the new migration is applied.

English gender, date of birth, and marital status determine their Khmer displays. House and street numbers convert numeric digits to Khmer while retaining letters. Birthplace, nationality, village, commune, district, province, and current address have separate English and Khmer fields. Nationality Note is calculated as Cambodian or International rather than accepting a manually supplied classification. A blank nationality remains unclassified.

The staff gender dropdown uses Student Enrollment's selection behavior with Khmer above English in both options and the selected label. Khmer uses the system's bundled Khmer OS Siemreap font. There is no separate Khmer gender textbox; choosing a gender retains the canonical English value, and the server derives the Khmer value automatically. Keyboard arrows, Home/End, Escape, and outside-click closing are supported.

Marital Status is also one bilingual dropdown, displaying Khmer above English with the bundled Khmer OS Siemreap font. There is no separate Khmer marital-status textbox. The saved English status determines the Khmer profile display automatically.

Phone Number, Alternative Phone Number, and Email appear in one row below Country of Birth, Province/City of Birth, and Nationality within Personal Information. Both phone controls use Student Enrollment's flag and separate dial-code treatment, starting at Cambodia (+855), with searchable country selection. Cambodian subscriber numbers display in spaced groups, and both contacts save full international numbers. Existing international dial codes are preserved. Email uses the shared mail icon and live validation: invalid input gets a red border and a message box at the field, with the existing error alert on blur. Work Email receives the same validation.

Date of Birth is one combined field: a readonly Khmer date above the editable English date, formatted as `12-Sep-2026`. It uses the shared premium calendar with month navigation, year selection, and direct DD-MMM-YYYY entry. Future dates are disabled. Khmer updates automatically, for example `១១ កញ្ញា ១៩៧៩`, and has no separate textbox. Marital Status occupies the former Khmer birth-date position. Place of Birth is a searchable Province/City dropdown populated from Location, with Khmer above English using the bundled Khmer OS Siemreap font. Both birthplace names are saved through this dropdown without a separate Khmer textbox; the server takes both names from that province record. Existing unmatched birthplace text is preserved when editing, and an already selected inactive province remains available.

Country of Birth uses the same searchable location picker, with a flag before Khmer above English. Cambodia is selected by default for new staff. Province/City choices belong to the selected country; changing country clears the previous province and both birthplace names. Country and province IDs are saved as nullable Location references, and the server rejects country/province mismatches. The staff profile also displays the saved birth country. Existing birthplaces can infer a country from a unique matching province when edited, without assigning assumed countries to existing database rows. Inactive saved countries and provinces remain available for editing.

Nationality uses Location's nationality names and country flags in a searchable picker, with Khmer above English in the options and selection. New staff default to Cambodian as in Student Enrollment. Selection fills Khmer Nationality and calculates the Cambodian/International note automatically; both form values are hidden. The server derives both names from the selected nationality record, independently of Country of Birth. Its nullable country reference is saved; existing unmatched nationality text and inactive saved selections remain available when editing. When a nationality name is missing, the corresponding country name is displayed as in Student Enrollment.

## Work schedules

Configure the default Time In and Time Out for Sessions 1 and 2. For each day, choose Not Working, Morning Only, Afternoon Only, or Full Day. Morning uses Session 1; afternoon uses Session 2. Blank daily times inherit the default session times; daily overrides take precedence. Changing defaults updates days that inherit them without replacing explicit overrides. Each configured session needs both times, Time Out must follow Time In, and sessions cannot overlap. Unspecified schedules remain unconfigured for older records.

## Work history

New profiles record their initial work assignment. When editing a profile, use Change Type, Effective Date, and Reason / Remarks for Change to identify promotions and transfers. Position, department, campus, hire/end dates, employment status/type, and schedule changes append a work-history entry. History keeps before/after details, effective date, actor name, and recording time. Personal-information edits and unchanged saves do not add work-change entries. Older records get a baseline snapshot on their first update, without inventing previous promotions or transfers. Staff Profile → Work History shows these saved details; later staff, department, position, or campus name changes do not rewrite them.

Resigned, Terminated, and Retired statuses require a leaving date. Leaving reasons can be recorded. HR campus assignments remain separate from the campus permissions of linked user accounts.

Education supports multiple qualifications with degree, major, institution, country, graduation year, and remarks. Legacy education dates and results remain editable. Previous Employment supports multiple employers with position, dates, and remarks, retaining optional employment type and current-employment details. Rows can be added and removed.

## Directory and optional HR details

The directory includes matching-profile counts, active staff, teaching staff, and active contracts ending within 30 days. Counts follow the current search, campus, category, and employment-status filters. Select filters apply immediately; search applies after a short typing pause and supports Khmer input composition. Mobile screens use staff cards; desktop screens use the directory table.

The directory uses the system pagination style with page arrows/numbers, record counts, a row-count selector, and Go to Page. It defaults to 20 rows and supports All, 20, 50, 75, and 100. All includes every matching record on one page. Pagination retains filters, and applying filters retains the row-count selection while resetting the page. Summary cards, filters, the full staff list, and pagination scroll together within the page content on computers and phones; the list has no separate vertical scrollbar. Pagination stays clear of the system footer. A back-to-top arrow appears after scrolling down 250 pixels and returns the whole page content to the top, respecting reduced-motion preferences. Staff names show Khmer above English; View, Edit, and Delete use icons with labels.

Staff Profile has Staff Information, Work Information, Qualifications, and Work History tabs. Work History uses a timeline with expandable before/after details. The create/edit form groups bilingual details and supports weekday schedule presets. Staff Photo follows the Create User upload flow: click/browse, drag and drop, or paste an image into the upload area, then crop using zoom, rotation, reset, and drag-to-reposition controls. JPG, PNG, and WEBP source images are limited to 2 MB. Crop and Upload selects a 400 × 400 JPEG in the form; it is stored when the staff profile is saved. Cancelling a crop preserves the previous selection or saved staff photo. HRM and login photos remain separate.

Optional additional fields include alternative phone, work email, identification document type/number/expiry, emergency contact address, contract type/number/start/end, probation end date, and supervisor. Contract dates must be ordered correctly, probation cannot end before the hire date, and a staff member cannot be their own supervisor. Contract and supervisor changes are included in work-history snapshots, including the supervisor's name at the time. Past history entries without these newer details continue to display normally.

## Staff CSV import and Excel export

HRM Settings → Import / Export offers a UTF-8 CSV template with two sample staff records, an Excel export of all saved staff, and CSV import for new profiles. Staff ID and Staff Name (English) are required; existing or repeated Staff IDs are reported without overwriting any profile. Each file supports up to 5,000 staff and 10 MB. Valid records are saved individually with their related records in a transaction. Invalid rows are skipped while other rows continue. A failed supervisor also skips dependent staff, without affecting unrelated records. File-level errors such as invalid headings or exceeding the row limit stop the import before any records are saved.

The result shows imported/skipped counts and all issues in pages of 100, with CSV row, Staff ID, field, problem, and Suggested Correction. Download Error Report exports all issues with the same columns. Suggestions cover every linked import field: country/birth province, nationality, address locations, Department, Position, Primary Campus, Working Campuses, and Supervisor Staff ID. Dropdown choices also suggest canonical values for gender, marital status, staff category, employment type/status, profile status, contract/document type, and each day's working period. Multiple linked-field errors and invalid dropdown choices in the same staff row are reported together. Misspelled names receive up to three close names; province/district/commune/village suggestions stay within the selected parent. Ambiguous Position matches show their Department, and supervisor suggestions show Staff ID with staff name. Each invalid working-campus item gets its own suggestion. A clear suggested parent can scope further suggestions for that rejected row, but no suggestion is applied or saved automatically. Ambiguous matches or names without a close match require manual selection. Download Failed Records exports only the skipped source records under the original headings, preserving their original data for correction and re-import. Corrected records receive their own new import result; successful records never need re-uploading. Reports are stored on the private local disk under the authenticated user's ID and are accessible only with that user's import permission and current report token. Their previous report is removed on the next completed import; session data contains only the summary and first page of issues.

Countries, birth provinces, nationality, address locations, departments, positions, and campuses use readable names rather than database IDs. Location matching accepts English or Khmer, checks the country/province/district/commune hierarchy, and rejects unknown or ambiguous names. Duplicate position names can be resolved by Department. Working Campuses use `|` between names. Supervisor Staff ID refers to the staff's own identifier, including a supervisor listed later in the same file; supervisor cycles are rejected. Dates accept `YYYY-MM-DD` or `DD-MMM-YYYY`; times use `HH:MM`. Numbered Education and Previous Employment columns support up to 50 records per section. The Excel export includes every saved education/employment record, keeps identifiers and phones as text, and freezes the first row and Staff ID column. Staff photos and login accounts are managed separately.

Import / Export permissions are separate for tab viewing, CSV template download, Excel export, and CSV import. The HRM menu, HRM Settings, and Staff View permissions are required; CSV import additionally requires Staff Create. Importing inactive profiles requires Staff Profile Status permission. Existing permissions and user assignments remain unchanged by the new permission migration.

## Staff-linked login accounts

HRM permissions appear together on the Permission page: Staff Management, HRM Settings, Department, Position, and the existing HRM menu destinations. Staff permissions cover viewing profiles/history, creating, editing all staff sections, deleting, and changing Profile Status separately. Department/Position permissions control viewing, creating, editing, status changes, deleting, printing, and Excel export. Their legacy Manage permission covers create/edit/status. HRM Settings shows only assigned tabs and action buttons; direct requests use the same checks. HRM menu permission is required, and Department/Position also require HRM Settings. The catalog migration preserves existing assignments and adds the corresponding parent permissions. Placeholder HRM modules currently have View permissions only.

HRM → HRM Settings groups Department, Position, and Import / Export in a two-column layout: setting tabs on the left and the selected content on the right. On phones, tabs appear above the content. Saving returns to the selected tab; lists retain search, sorting, pagination, Print, and Excel. The menu and actions respect the assigned HRM permissions, with full access for Super Admins. The original settings endpoints and records remain available; `/hrm/departments` and `/hrm/positions` open their tabs in HRM Settings. Additional settings can be added to the settings tab registry and given their own form partials.

Departments support multiple levels using the nullable `access_departments.parent_id` foreign key. In HRM Settings → Department, select Parent Department or leave “None — Main Department”. Existing departments retain their IDs and initially remain main departments. Department choices show their full path (for example, Academics › Registrar) in Staff Management, Create User, Position, Role, access permissions, dashboard assignments, and notification recipient forms. Department lists and related profiles/reports also show the hierarchy. Active subdepartments remain selectable when their parent is inactive; permissions and notification recipients continue to use the explicitly selected department IDs without inheriting parent assignments.

Department and Position lists share the same header layout: title, a compact search field aligned right before Print, Excel, and the New Department/Position button. New opens a popup with blank Name and Code, no parent/department, and Active status. Edit opens the same popup with saved values; validation errors reopen it with attempted values. Both use the same responsive popup, light header text, reset behavior, and success notice. Settings tabs follow Academic Reports navigation: collapsed to an icon rail on computers, hidden below the tabs header on phones, and expanded with the header toggle. Every page opens with tabs collapsed; icons provide accessible labels and desktop hover tooltips.

Parent choices exclude the department being edited and its descendants. Server validation also rejects self-parenting, descendants, and circular ancestry; hierarchy edits lock the department rows inside a transaction. Parents with children and departments used by staff, positions, users, roles, or permissions cannot be deleted. Reparenting changes neither staff/user assignments nor previously saved work-history snapshots. Older update callers that omit `parent_id` preserve the existing parent.

In Administrator → Users, selecting an available staff profile fills staff ID, English name, gender, date of birth, phone, department, position, and email (work email when available). Choosing another staff profile clears missing details from the previous selection. Username, password, role, and login-campus assignments remain independently configurable. Staff who already have a login are excluded from the create selector; an existing linked profile remains available when editing its account. Autofill runs when the selection changes, so merely opening an existing account does not replace its saved details.

User information is saved on the login account without updating HRM staff details or work history. Login photos use the user account's separate photo field and `users` storage directory; selecting a staff profile never copies its HRM photo. Users can change their login photo through My Profile while the HRM photo is preserved.

## Deployment

Apply `php artisan migrate --path=database/migrations/2026_10_13_000001_expand_staff_profiles_and_work_history.php` and `php artisan migrate --path=database/migrations/2026_10_13_000002_add_staff_contract_and_identity_details.php`, then run `npm run build`. These migrations add nullable profile fields, education fields, and a work-history table; they do not change existing campus assignments or linked-user access.

## Current address

The Create/Edit Staff form has a Current Address card with a dark blue header. Country, Province/City, District/Khan, Commune/Sangkat, and Village use searchable Location dropdowns, with Khmer OS Siemreap above English and a flag for Country. The five dropdowns share one desktop row and stack on phones. Cambodia is the default for new profiles. Each parent selection clears its descendants and loads only matching active locations; saved inactive selections remain available on edit. Older text-only addresses are matched only when unambiguous, otherwise their existing text remains available.

English and Khmer address summaries are read-only and update from the selected locations and house/street inputs. House and street digits convert automatically to Khmer. Location IDs are stored separately from their bilingual names, and the server verifies the parent hierarchy and derives names from Location records. Apply `php artisan migrate --path=database/migrations/2026_10_13_000006_add_address_locations_to_staff.php` when deploying these address dropdowns, then rebuild assets.

## Identification

Identification uses a dark blue card with a Document Type selector. National ID shows ID Number, Issue Date, and Expiry Date; Passport shows Passport Number and both dates; Other adds Document Name alongside Document Number and both dates. The selector and relevant fields share one desktop row and stack on phones. Hidden inputs are excluded from submission. Issue Date and Expiry Date use the shared premium calendar, with month navigation, a year selector, direct date entry in DD-MMM-YYYY format, and ISO dates submitted to the server. Expiry Date cannot precede Issue Date in either the calendar or typed input, and saved names and dates appear in the staff profile. Clearing Document Type clears its saved identification details. Apply `php artisan migrate --path=database/migrations/2026_10_13_000007_add_staff_identity_issue_details.php` and rebuild assets when deploying.

## Emergency contact

Emergency Contact uses a dark blue card with Contact Name, Contact Phone, Relationship, and Emergency Contact Address in one desktop row. The address spans two field widths and expands for longer text; phones stack the fields. Contact names uppercase while typing and when saved. Contact Phone reuses the staff phone input with country flags, Cambodia +855 by default, Cambodian digit grouping, and international number storage. Remarks are hidden from Create/Edit Staff; existing saved remarks are preserved when the form is saved.

## Work assignment controls

Hire Date, Position, Department, Reports To / Supervisor, and Primary Campus share one desktop row and stack on phones. Hire Date uses the shared premium calendar with DD-MMM-YYYY display and ISO storage. Working Campuses is a searchable multi-select dropdown with keyboard navigation and multiple selections that keep the menu open. Selecting a Primary Campus immediately includes it in Working Campuses and marks it Primary; it cannot be removed while primary. Changing primary preserves other working assignments. Saved inactive working campuses remain available when editing. Reset restores saved selections, and existing server logic includes the primary campus even when a client omits it from the working list.

Staff Category, Employment Type, Working Campuses, Employment Status, and Resignation / Termination / Retirement Date share a second desktop row and stack on phones. Profile Status sits at the left of the third row, with Leaving Reason on the right spanning two field widths. The resignation date uses the same premium calendar as Hire Date and prevents dates before Hire Date. Resignation Date and Leaving Reason are hidden and excluded from submission while Employment Status is Active; switching to another status restores the visible controls without discarding entered values. Profile Status uses the shared animated ON/OFF switch style, with the saved boolean submitted as 1 or 0 with the staff form. New staff default to ON; editing and resetting restore the saved state. Changing this switch does not send a separate status request or change the linked login account.
