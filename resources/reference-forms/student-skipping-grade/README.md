# Student Skipping Grade references

When an approved skipping-grade request has already enrolled a student in the next academic year, class and selected-student promotion keep that placement and promote the remaining students. The promotion preview marks these students as `Already enrolled — Grade Skipping`, shows the approved grade/class/year and approval number, and reports separate promoted and already-enrolled counts. An existing enrollment without a matching approved request and valid linked placement requires review; promotion does not overwrite it. The one-enrollment-per-student-per-year database constraint remains in place.

Preparing a skipping-grade enrollment for next year leaves the current enrollment active. The academic-year lifecycle completes it when the current year is finished. Bulk promotion does not create another skipping-grade history entry or change the approved request, signature, or stamp.

If normal promotion already created a next-year enrollment, a skipping request can use the original completed enrollment when a valid promotion links the two. The request shows `Already Promoted` and the existing placement. Pending or rejected requests leave that placement unchanged. Central Office approval changes the grade/class on the same enrollment, preserving its ID, year, campus, status, and enrollment date. History retains the original promotion and records the existing next-year grade before and after skipping. The requested grade must exceed the already-promoted grade. Changes to the linked placement after saving the request require review before submission or approval; unrelated, cancelled, or withdrawn enrollments cannot be overwritten. A promotion linked to an approved skipping placement cannot be cancelled through normal promotion cancellation.

The School Logo is selectable in both editors. Dragging, arrows, and Left/Top offsets move it relative to its original position; Width and Height resize its container while the Branding image keeps its proportions. Each form saves its logo layout independently. Reset Selected Object or Restore Original Layout restores its original size and position.

Text objects support the Bullets checkbox in both editors. Each non-empty content line becomes a bullet item with a hanging indent; blank lines preserve spacing. The saved content and automatic values remain intact when bullets are switched off. Preview and print use the same formatting.

Added checkboxes can use the editor's Checkbox Value selector to link to an existing request criterion, approval age/school decision, or student obligation. Linked checkboxes read saved record values and do not create additional entry options. Remove the original checkbox and link its replacement to the matching value, then save the template. Choosing New form option retains the separate custom-option workflow.

Approval numbers combine the Approval Settings prefix, the student's current academic year's saved AY Code (`academic_year_code`), and the padded request ID. For a request from 2025–2026 to 2026–2027, the code comes from 2025–2026. A missing current-year AY Code must be filled in Academic Year settings before approval. Changing the code affects future approvals; issued numbers remain unchanged. The template sample uses the saved code for its current year (2025–2026), or the placeholder `AY-CODE` if that year has no code.

These permanent copies preserve the supplied request and approval examples after the sample files in Imports are deleted. Printed forms use the independent Blade templates, CSS, saved request data, and privately uploaded approval signature/stamp. They do not load these reference images or files from Imports.

The Skipping Grade workspace includes Requests, Campus Settings, Approval Settings, Customize Request Form, and Customize Approval Form. The Permission page lists the submenu, each tab, and request, approval, print, settings-save, and template-edit actions independently. Settings and template tabs can be granted read-only; template editing includes adding/removing objects, saving, discarding, and restoring. Request and approval templates are stored separately in `tb_skipping_grade_settings` and apply to future printouts across campuses. Text in braces fills from each request; signatures and stamps still come from the approved record's frozen snapshot.

Campus Settings stores Class Teacher, KH-Coordinator, VSP, and School Principal names separately for each campus in `tb_skipping_grade_campus_settings`. Grant `student-skipping-grade.campus-settings` to view the tab and `student-skipping-grade.save-campus-settings` to save names. Campus users can view and update settings only for their assigned campuses; the same restriction is enforced for direct requests. Super administrators can configure all campuses. Selecting a student for a new request fills the saved names from that student's campus. The request may override those names without changing campus settings. Editing existing requests retains their saved committee names. Central committee names continue to come from Approval Settings. Migration `2026_10_08_000005_add_skipping_grade_campus_settings.php` creates the table and adds both permissions; administrators must grant them to campus staff.

Users with the Requests tab can filter and view students and requests across campuses. Campus users can create, edit drafts, and submit requests with the corresponding action permission and access to the student's assigned campus. Cross-campus selections remain viewable and show a notice with saving disabled. Printing requires the Print permission. Central approval and rejection require explicit permissions and can operate across campuses. Central Office: Edit Draft and Submitted Requests (All Campuses) is a separate permission (`student-skipping-grade.central-update`) that permits edits before approval across campuses without granting creation or approval. Submitted edits preserve the submission status, signed date, and uploaded signed request; approved and rejected requests remain locked. Removing a tab permission disables its dependent actions in the Permission page and server checks. Migration `2026_10_08_000003_add_skipping_grade_tab_permissions.php` preserves existing request access and splits existing settings access into the new tab/edit permissions without overwriting explicit choices. Migration `2026_10_08_000004_add_central_skipping_grade_edit_permission.php` adds Central editing; administrators must explicitly grant it to Central staff.

Editors support text, bundled fonts, 6–60 pt sizes, colors, bold, drag movement, and position offsets in millimeters. Restore Original Layout resets the editor; Save Template commits that reset. Discard Changes returns to the last saved template. Concurrent saves of the same form require reloading rather than overwriting another user's edits.

Both previews open read-only with editor controls hidden. Edit Report enables the controls, selection, dragging, and keyboard editing. Finish Editing hides the controls and locks the preview again without saving or discarding changes; Save Template remains the explicit save action.

Dotted lines, score borders, and checkboxes are selectable objects with size and border controls. Users can add text boxes, boxes, dotted lines, and premium checkboxes, and remove objects. Added checkboxes have a Form Option Label and appear as selectable Additional Request Options or Additional Approval Options on the corresponding entry form. Add a text box beside a checkbox for its printed label. “Selected by default on new forms” only controls initial form selections and the sample preview; actual print ticks come from the saved student request or approval. Request selections and their labels are stored under `criteria.custom_options`; approval selections and labels are stored under `approval_snapshot.custom_options`. Both reuse existing JSON columns. Labels remain in saved record details after template edits, and unknown or removed checkbox keys are rejected on save. Original checkboxes continue to follow the request data. Removing an original object keeps it in the object selector with “(Removed)”; Reset Selected Object restores it. Added objects are deleted when removed.

Requests support the current or immediately next operational regular academic year. Requested classes are scoped to that year or shared classes. Same-year approval updates the existing enrollment; next-year approval creates a separate enrollment, pending until the requested year starts, and preserves the source enrollment. Existing target-year enrollments are never overwritten. Both enrollments are linked through before/after history, and the approved request stores its target enrollment ID. The printed `{academic_year}` and `{requested_academic_year}` values use the requested year; `{source_academic_year}` provides the original year. Legacy requests default to their original academic year.

On approval, the target enrollment's Remarks receive a short automatic line: `Skipped from 3B | Approval No: SG2627-001`, using the saved source grade short name and class and the issued approval number. Existing target remarks are preserved. Pending and rejected requests do not add remarks. This applies to same-year changes, new next-year enrollments, and reused normally promoted enrollments; it does not retroactively change earlier approvals.

Both before/after skipping approval history entries also store this short remark in Notes, appended after the request reason when present. The Enrollment History popup displays these notes in a Remarks column. Earlier history entries remain unchanged.
