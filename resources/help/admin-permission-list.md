## Before you start

Open **Administrator → Roles & Permissions → Permission List** with permission to manage access settings. This tab lists permission definitions; it is different from assigning access to a role, department, or user.

## Find a permission

Search by Module, Permission Code, Permission Name, or Action. Use the table headings to sort and the pagination controls to inspect additional results.

| Field | Meaning |
| --- | --- |
| Module | The feature area that owns the permission |
| Permission Code | The identifier checked by the application |
| Permission Name | A readable description |
| Action | The operation or submenu represented |
| Linked data | References associated with the permission |

## Configure who can use it

Use **Permissions by Dept.**, **Permissions by Role**, or the **Users** permission area to grant access. Creating a definition alone does not add a new working screen or implement a new application action.

## Create or remove definitions

The Create Permission form requires a name, unique code, module, and action. Only create a definition when it corresponds to an implemented application permission or an approved configuration task.

Deletion can affect roles, departments, users, and application checks. Review linked data and any confirmation or restriction message before removing a definition. Prefer correcting the intended access assignment when the problem is simply that a user has too much or too little access.

## Print or export access reports

Use the page's **Print** or **Excel** menu and choose Permission List, Permission by Department, Permission by Role, or Permission by User.

Review the selected report and resulting data before sharing it. These reports describe configured permissions; campus, record-level, and module-specific restrictions still apply at runtime.
