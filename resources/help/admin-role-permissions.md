## Before you start

Open **Administrator → Roles & Permissions → Permissions by Role** with permission to manage access settings. Changes affect the role's assigned users.

## Choose the role and department

1. Use the searchable **Select Role** dropdown.
2. Verify the selected role after the page reloads.
3. Review **Role Department** beside it.
4. Select the intended department, or No Department if appropriate.

The labels float inside the boxes above the selected text. Choosing Role Department does not save it immediately; it is submitted with **Save Role Permissions**.

## Set main menus, submenus, and actions

Search for the required module or action. Enable the main menu before its submenu and actions. Review tab-specific permissions where the module offers them.

Use Full Access only when the role should receive that broad set of grants. Campus and record-level restrictions may still apply.

## Save and verify

Choose **Save Role Permissions**. This saves the selected Role Department and the role's permission grants. Check the success message and reopen the role if needed to verify the result.

Inspect an affected user's role, department, direct grants, and campuses before concluding that a shared role change has added or removed all access.

## Common problems

- **Switch cannot be enabled:** check the required main menu or submenu first.
- **Saved grant has no effect:** check role status and campus assignment, then refresh the target module.
- **Only one user needs access:** consider a reviewed user-specific grant instead of broadening the shared role.
