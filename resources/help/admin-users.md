## Before you start

Open **Administrator → Users** with a super administrator account. User creation, editing, exports, and deletion are administrative operations.

## Create an account

1. Use the page's new-user action.
2. Enter the staff ID, name, username, and email, and any relevant staff profile or contact details.
3. Select the department, position where appropriate, and required role.
4. Review login identifier options and account status.
5. Choose the campus assignments or the intended global scope.
6. Set and confirm the password when supplying one.
7. Save and verify the account in the list.

Usernames, emails, and staff IDs must be unique. A supplied password requires confirmation and at least eight characters. Follow validation messages instead of reusing another person's account details.

## Review role and campus scope

Global scope is different from choosing individual campuses. Verify the intended scope before saving. The user form saves the selected role assignment and campus list, so review both when editing an existing account.

Additional permission selections are user-specific grants. Reusable access should normally be configured through Roles & Permissions rather than repeated separately on every account.

## Edit an existing account

Find the correct staff ID, username, and email before opening edit. Review all submitted fields, role, campus assignments, and status, then save. Leave the password empty when no password change is intended for an existing user.

## Deactivate or delete

Use the available status or deletion controls only after checking the target account. The system prevents deactivating your own logged-in account and protects the last super administrator from deletion.

Deleting a login account is different from deleting a staff or student profile. Read any confirmation or validation message before proceeding.

## Verify the result

Review the saved account and access configuration. If a user still cannot open a feature, inspect the role, department, user grants, and campus scope rather than changing their password repeatedly.
